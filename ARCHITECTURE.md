# ScrapeBadger — Architecture

`scrapebadger` is an async Rust SDK **and** CLI (one crate, a library and a binary
of the same name) for the [ScrapeBadger](https://scrapebadger.com) web-scraping
platform. It covers **137 endpoints** across 7 platforms, plus real-time
Twitter Streams.

- **Docs index:** <https://docs.scrapebadger.com> · machine index: <https://docs.scrapebadger.com/llms.txt>
- **API reference:** <https://docs.scrapebadger.com/api-reference/introduction>
- **Authentication:** <https://docs.scrapebadger.com/authentication> — `x-api-key` header
- **Rate limits:** <https://docs.scrapebadger.com/rate-limits> · **Credits & pricing:** <https://docs.scrapebadger.com/credits-and-pricing>

## How the client is shaped

One entry point, a namespace per platform, mirroring the official Python/Node SDKs:

```rust
use scrapebadger::ScrapeBadger;

let client = ScrapeBadger::from_env()?;                  // SCRAPEBADGER_API_KEY
let product = client.amazon().get_product("B08N5WRWNW", Default::default()).await?;
let flights = client.google().flights_search(scrapebadger::google::FlightsSearchParams {
    departure_id: Some("DEL".into()),
    arrival_id:   Some("BOM".into()),
    outbound_date: Some("2026-07-01".into()),
    ..Default::default()
}).await?;
```

Every endpoint is `client.<platform>().<method>(<path args…>, params)`. Inputs are
plain `Default`-able `*Params` structs — set the fields you need, spread the rest.

## Module map

```
crates/scrapebadger/src/
  lib.rs              ScrapeBadger client, builder, platform accessors
  main.rs             CLI binary (feature "cli")
  core/
    client.rs         reqwest transport: auth, retries, error mapping, send<T>()
    config.rs         Config + defaults (base URL, timeout, max_retries)
    error.rs          typed Error enum (401/402/422/429 + Api fallback)
    request.rs        QueryParams builder (used by generated code)
    pagination.rs     cursor_stream / page_stream helpers
  <platform>/
    mod.rs            hand-written: module docs + re-exports
    generated.rs      @generated: platform handle, methods, param + response models
  twitter/stream.rs   hand-written: WebSocket consumer + HMAC webhook verify
specs/                vendored OpenAPI specs (source of truth for codegen)
xtask/                the code generator
```

## Codegen pipeline

`generated.rs` is produced by `cargo run -p xtask -- gen` from the 7 specs in
`specs/`. The specs were generated by different backends and are inconsistent, so
the generator normalizes:

- **4 nullable encodings** (`nullable:true`, `anyOf:[T,null]`, `type:[T,"null"]`,
  `oneOf:[$ref,null]`) → `Option<T>`.
- **Untyped Reddit 200 bodies** → `serde_json::Value`.
- **Anonymous inline objects** (Amazon/Vinted) → synthesized struct names.
- **FastAPI operationIds** (`flights_search_api_v1_flights_search_get`) → clean
  method names derived from the path/prefix; redundant platform tokens stripped.
- **Genuine unions / open maps** → `serde_json::Value` / `HashMap<String, _>`.
- Hard-coded base URL + `x-api-key` + the `/v1` vs `/api/v1` path split (Google).

Output is deterministic (re-running `gen` yields no diff) and checked into the repo.

## Transport behaviour

- **Auth:** `x-api-key` header on every request; key from arg or `SCRAPEBADGER_API_KEY`.
- **Base URL:** `https://scrapebadger.com` (overridable). Paths carry their own
  version prefix, so the client just concatenates `base_url + path`.
- **Retries:** 502/503/504 and transient transport errors, exponential backoff
  (1,2,4,8…s capped 30s), `max_retries` default 10; honors `Retry-After`.
- **Errors:** `401→Unauthorized`, `402→PaymentRequired`, `422→Validation`,
  `429→RateLimited`, else `Api { status, message, body }`.
- **Pagination:** `core::pagination::{cursor_stream, page_stream}` turn a
  fetch-one-page closure into a `Stream` (Twitter/Google cursors, Amazon/Vinted pages).

## Twitter Streams (real-time)

`feature = "stream"`. Monitors / Filter Rules / Webhooks are CRUD'd via the
generated `twitter()` methods; delivery is consumed via:

- **WebSocket:** `client.twitter().stream_events().await?` →
  `Stream<Item = Result<TweetEvent>>` (connects to `wss://…/v1/twitter/stream`).
- **Webhooks:** `twitter::stream::verify_webhook_signature(secret, body, header)`
  validates the `X-Signature-256: sha256=…` HMAC-SHA256 signature.

Docs: <https://docs.scrapebadger.com/twitter-streams/overview> ·
[WebSocket](https://docs.scrapebadger.com/twitter-streams/websocket) ·
[Webhooks](https://docs.scrapebadger.com/twitter-streams/webhooks)

## CLI

`scrapebadger <command>` — typed conveniences (`account`, `scrape`, `flights`,
`google-search`, `amazon-search`, `amazon-product`, `twitter-search`,
`reddit-post`) plus `raw --method <M> <path> [-q k=v]… [-d <json>]` which reaches
**any** of the 137 endpoints. Reads `SCRAPEBADGER_API_KEY`, prints pretty JSON.
CLI command reference: <https://docs.scrapebadger.com/cli/commands>
